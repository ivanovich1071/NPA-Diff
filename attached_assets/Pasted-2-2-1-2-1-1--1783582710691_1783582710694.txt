2. Требования к системе
2.1. Функциональные требования
2.1.1. Загрузка документов
№	Функция	Описание
1	Загрузка файлов	Поддержка загрузки двух файлов (старая и новая редакция) в форматах: DOCX, PDF, TXT.
2	Загрузка по URL	Поддержка загрузки документов по прямой ссылке с Национального правового Интернет-портала (pravo.by).
3	Ручной ввод текста	Возможность вставки текста обеих редакций в текстовые поля.
2.1.2. Извлечение и нормализация текста
№	Функция	Описание
4	Извлечение текста	Извлечение текстового содержимого из загруженных файлов (DOCX, PDF).
5	Нормализация	Приведение текста к единому формату: унификация пробелов, приведение к одному регистру (опционально), удаление лишних символов.
6	Структурирование	Разбиение текста на структурные элементы: разделы, главы, статьи, пункты, подпункты (на основе разметки документа).
2.1.3. Сравнение редакций (основная функция)
№	Функция	Описание
7	Постатейное сравнение	Сравнение текста постатейно (по пунктам, подпунктам) с выделением различий.
8	Выделение изменений	Автоматическое выделение следующих типов изменений: • добавления (новый текст) — выделение зелёным; • удаления (исчезнувший текст) — выделение красным (зачёркивание); • замены (текст изменён) — выделение жёлтым; • перемещения (текст перенесён в другую часть документа) — выделение синим.
9	Сводная таблица изменений	Формирование таблицы со списком всех изменений по статьям/пунктам с указанием типа изменения и краткого описания.
10	Семантический анализ изменений	Использование LLM для анализа сути изменений и формирования краткого резюме: «что изменилось и каковы последствия».
2.1.4. Генерация отчёта
№	Функция	Описание
11	Формирование отчёта	Генерация отчёта о сравнении в форматах: DOCX, PDF, HTML.
12	Содержание отчёта	Отчёт должен включать: • заголовок (вид акта, номер, дата принятия); • сводную таблицу изменений; • полный текст обеих редакций с визуальными выделениями; • аналитическое резюме (краткое описание ключевых изменений); • дату и время генерации.
13	Экспорт	Возможность скачать отчёт в выбранном формате.
2.1.5. Дополнительные функции
№	Функция	Описание
14	История сравнений	Сохранение истории всех выполненных сравнений (метаданные: дата, пользователь, названия документов).
15	Контекстный чат по документу	Возможность задать вопросы LLM по содержанию изменений (например: «Как новые требования влияют на процедуру согласования?»).
16	Human-in-the-loop	Обязательный этап проверки результатов сравнения специалистом перед формированием финального отчёта (в соответствии с реформой Закона № 99-З и принципом человеческого контроля).
2.2. Технические требования
2.2.1. Архитектура
Компонент	Требование
Тип архитектуры	Клиент-серверное веб-приложение, разворачиваемое на платформе Replit.
Клиентская часть	Одностраничное приложение (SPA) на React (или Vue.js) с адаптивным дизайном.
Серверная часть	REST API на Python (FastAPI), запускаемый в Replit как веб-сервис.
База данных	SQLite – встроенная реляционная БД, хранящаяся в постоянном хранилище Replit.
Хранение файлов	Загруженные документы временно сохраняются в файловой системе Replit (папка uploads/), очищаются после обработки.
Внешние API	Интеграция с Mistral AI API (основной) и OpenRouter API (резервный) для вызова LLM.
2.2.2. Используемые модели ИИ
Модель	Назначение	Источник
Mistral Small 4 (119B параметров, 6.5B активных)	Основная LLM для семантического анализа, сравнения, генерации резюме и ответов на вопросы	Mistral AI (API)
Контекстное окно	256K токенов	—
Стоимость API	$0.15 / млн токенов (вход), $0.6 / млн токенов (выход)	—
Qwen3.7-Max (флагманская модель)	Резервная LLM для документов >256K токенов и при недоступности Mistral	OpenRouter (Alibaba Cloud)
Контекстное окно	1,000,000 токенов	—
Стоимость (OpenRouter)	$1.25 / млн токенов (вход) / $3.75 / млн токенов (выход) со скидкой 50%	—
Стратегия использования:

По умолчанию → Mistral Small 4.

При превышении 256K токенов или ошибке API → автоматическое переключение на Qwen3.7-Max через OpenRouter.

2.2.3. Инфраструктурные требования (Replit)
Параметр	Требование
Платформа	Replit (replit.com) – облачная IDE и хостинг.
План	Рекомендуется Hacker Plan ($20/мес) для обеспечения стабильной работы, наличия постоянного хранилища и большего количества ресурсов. Допустим бесплатный план на этапе прототипа, но с ограничениями.
Языки / стек	Бэкенд: Python 3.10+ с FastAPI, Uvicorn. Фронтенд: React 18+ (или Vue 3) с Vite.
База данных	SQLite (файл data.db в постоянном хранилище Replit).
Переменные окружения	Хранение API-ключей (MISTRAL_API_KEY, OPENROUTER_API_KEY) в Secrets Replit.
Деплой	Автоматический деплой при пуше в подключённый Git-репозиторий; Replit сам запускает сервер через main.py.
Домены	Replit предоставляет поддомен вида project-name.username.repl.co; возможно подключение собственного домена.
2.2.4. Требования к производительности
Параметр	Значение
Время загрузки двух файлов (до 50 стр.)	≤ 5 сек
Время сравнения (до 50 стр.)	≤ 30 сек (зависит от API)
Время генерации отчёта	≤ 15 сек
Одновременные пользователи (начало)	до 5
Доступность	99% (с учётом внешних API)
2.2.5. Требования к информационной безопасности
№	Требование
1	Все данные (тексты НПА, результаты) хранятся только в постоянном хранилище Replit; передача во внешние API – только обрабатываемые фрагменты.
2	Аутентификация: логин/пароль (хеширование bcrypt) с возможностью интеграции LDAP/AD (опционально).
3	Ролевая модель: администратор, пользователь, эксперт.
4	Журналирование всех действий в БД.
5	Human-in-the-loop: финальный отчёт утверждается экспертом.
2.2.6. Требования к интеграции
№	Интеграция	Описание
1	Национальный правовой портал (pravo.by)	Загрузка по URL.
2	Mistral AI API	Основной канал для LLM.
3	OpenRouter API	Резервный канал (Qwen3.7-Max).
4	(Опционально) СЭД	Интеграция с корпоративными системами на следующих этапах.
2.2.7. Требования к интерфейсу пользователя
Язык интерфейса: русский / белорусский (переключатель).

Пошаговый процесс: загрузка → сравнение → просмотр → отчёт.

Две колонки с подсветкой изменений (цветовая кодировка).

Переключение режимов: «только изменения» / «полный текст».

Адаптивный дизайн для ПК и планшетов.

3. Этапы разработки и сроки (в среде Replit)
Этап	Содержание	Срок
Этап 1	Создание и настройка проекта в Replit
• Регистрация в Replit, создание нового проекта (Python + React).
• Подключение Git-репозитория.
• Настройка переменных окружения (Secrets) для API-ключей.
• Установка зависимостей (FastAPI, Uvicorn, python-docx, PyPDF2, react, vite, etc.).
• Проверка работоспособности базового сервера.	[1–2 дня]
Этап 2	Разработка бэкенда (FastAPI)
• Модуль загрузки/извлечения текста из DOCX/PDF/TXT.
• Модуль нормализации и структурирования.
• Модуль сравнения (алгоритм diff + интеграция с Mistral/OpenRouter).
• Модуль генерации отчётов (DOCX, PDF, HTML).
• Модуль истории (SQLite).
• Модуль аутентификации и ролей.
• REST API эндпоинты.	[5–7 дней]
Этап 3	Разработка фронтенда (React/Vue)
• Интерфейс загрузки документов.
• Страница сравнения (две колонки с подсветкой).
• Таблица изменений.
• Кнопки экспорта отчёта.
• Чат-виджет для вопросов по документу.
• Личный кабинет (история, профиль).	[4–6 дней]
Этап 4	Интеграция и тестирование в Replit
• Сквозное тестирование всех сценариев.
• Проверка работы с реальными API.
• Нагрузочное тестирование (имитация 5 пользователей).
• Проверка безопасности (доступ, журналирование).
• Исправление ошибок.	[2–3 дня]
Этап 5	Развёртывание и ввод в эксплуатацию
• Финальный деплой на Replit (production).
• Подготовка документации (руководство пользователя, администратора).
• Обучение пилотной группы (2–4 часа).	[1–2 дня]
Итого		~15–20 рабочих дней
